# API 额度使用计划（尚未接入）

本计划服务于 LinkNest 的开源维护，当前产品仍是无需 API 的静态网站。本文不是已部署功能、已获额度或已取得效果的声明。

官方项目依据：[Codex for Open Source](https://developers.openai.com/community/codex-for-oss)，核对日期 2026-10-21。官方将 PR 审查、维护自动化、发布等 OSS 工作列为 API 额度用途；具体资格及额度以审核结果为准。

## 首轮试点

先在 30 个维护任务上做人工对照，再决定是否扩至 200 个任务。只使用仓库公开代码、合成备份和脱敏问题；不提交个人收藏。首轮额度分配目标是：60% 回归测试生成，25% 候选补丁审查，15% 发布说明和贡献文档检查。百分比是预算规划，不是已经产生的调用占比。

| 任务 | 输入 | 产物与验收 |
| --- | --- | --- |
| 导入与去重边界测试 | core.js、合成用例和明确的行为约束 | 能在故障版本失败、在修复版本通过的回归测试；维护者审查是否重复或无效 |
| 安全相关变更审查 | 脱敏 diff、SECURITY.md、预期行为 | 每条发现附文件位置、复现及影响；人工复现后统计误报 |
| 发布与贡献文档 | 已合并 diff、已通过的测试记录 | 标明事实与未完成项；维护者确认后发布，不自动发评论或合并 |

## 可复现的评估方法

现有 `test/import.test.js` 提供规范化重复地址、ID 冲突、批内重复、幂等性、输入不变性、超限及类型错误的确定性测试。它们是后续评估的基线，不是模型性能结果。

后续在独立评估分支构造有明确预期的故障版本，例如去掉协议限制、使用字符数代替字节数、遗漏 ID 冲突处理、合并覆盖现有标题。使用未提供给模型的断言评估候选测试，防止只验证模型自己的实现。只有有意注入的本地故障样例，不对真实第三方服务进行攻击。

每次运行记录：任务编号、输入提交、模型标识、提示版本、输入/输出 token、实际费用、耗时、测试是否通过、是否捕获故障、人工接受/拒绝原因。首轮报告给出完整分母，不把局部成功率说成总体质量。发布不含敏感数据的提示、用例与汇总结果，使其他小型开源项目可以复用。

## 执行与预算边界

未来接入时仅允许维护者手动启动。服务端保存密钥，任务环境只读、无生产权限；模型输出只作为待审查建议，不执行来自 PR、Issue 或文档中的嵌入指令。不自动触发外部 PR 的带密钥任务。

获得额度并确定模型后，按当时官方价格测算单任务成本；先设置明确的单任务 token、重试次数、任务数量和总预算上限。试点最多 30 个任务，每个失败任务最多重试一次，达到配置预算即停止，不自动购买额度或放大运行规模。当前没有调用 API，也没有费用或提效数据。
